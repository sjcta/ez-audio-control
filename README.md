# Ez Audio Control

**外接显示器后，Mac 的音量键调不了音量？**

Ez Audio Control 是一个**免费、开源、专注音量控制**的 macOS 菜单栏小工具。用熟悉的音量键、已映射为系统音量指令的鼠标操作和菜单栏滑杆调节当前输出；对于系统音量不可写的兼容输出，自动尝试软件衰减，**无需安装额外驱动**。

[English](README.en.md) · [MIT 许可](LICENSE) · [隐私说明](PRIVACY.md) · [参与开发](CONTRIBUTING.md)

> **当前为 0.1.44 开发预览源码，尚无正式下载包，也未提供已公证的发行版。** 想试用请先查看[运行要求](#运行要求)和[从源码构建](#从源码构建)；本地构建属于开发版本。

## 能做什么

- **自动选择音量控制方式**：系统音量可写时使用原生音量；不可写时自动尝试软件衰减，是否可用取决于系统权限和输出格式。
- **沿用熟悉的操作**：支持键盘音量增减、静音，以及已映射为系统音量指令的鼠标操作。普通滚轮或横滚不会自动变成音量控制。
- **菜单栏随手调节**：左键打开滑杆、音量数值、静音和输出设备列表；音量指令触发顶部 HUD，未就绪时显示等待状态。

另外还提供：

- 已配对的蓝牙音频设备列表，包括未连接设备；你点选后才连接并切换输出。
- “HUD”和“完整”两种显示模式：菜单栏只保留图标，或同时显示音量数字；两种模式都保留顶部 HUD。中英文跟随系统语言。
- 可选音量反馈音效与登录时启动；软件模式的反馈音跟随已确认的软件增益。
- 菜单底部独立的“声音设置…”入口，直达 macOS 声音设置。

软件音量的 100% 是进入处理链路的原始音频，0% 是静音；只衰减，不放大，也不写显示器或外部音箱的硬件音量。

## 为什么开发这个软件

我的 Mac mini 接上显示器后，声音能正常播放，macOS 的系统音量却无法调节。我只想继续用熟悉的操作调音量，于是做了这个免费、开源、尽可能轻量的小工具。

现有方案中也有免费工具；Ez Audio Control 希望提供一个专注音量控制的选择。相关资料见[社区讨论与常见解决路径](Docs/BACKGROUND.md)。

## 运行要求

| 项目 | 要求 |
| --- | --- |
| 架构 | Apple Silicon；未提供 Intel App 构建 |
| 系统 | 部署目标 macOS 14+；软件音量要求 macOS 14.2+ 与兼容的输出格式 |
| 依赖 | 仅系统框架，无第三方运行依赖 |

兼容性验证限于当前开发机、离线假设备与组件检查，不保证所有 macOS 版本、显示器或音频设备可用。

**睡眠、显示器唤醒和长时间运行的恢复仍在观察。** 软件音频链路清理或恢复时声音可能短暂中断；退出或故障时原始音频可能恢复，不能把软件衰减当作硬件音量上限或听力保护。第一次试用前，请暂停播放并把外部音箱调至安全音量。

## 使用与权限

1. 打开 App 后，左键菜单栏图标调节当前输出或点选设备；右键进入显示模式、音效和登录项设置。
2. 音量键与已映射的鼠标音量指令需要你在系统设置中授予系统控制许可。新系统可能称“设备控制和数据访问”，旧系统称“辅助功能”；App 提供对应入口，授权后自动接管。
3. 系统音量不可写的输出会自动尝试软件模式；首次 macOS 系统音频捕获提示由你决定。它处理系统输出音频，不读取物理麦克风，不保存音频。
4. 蓝牙许可只在你显式使用蓝牙入口时请求；App 不扫描新设备、自动配对或自动连接。

只运行一份 App，避免多个音量工具同时处理同一条指令。遇到问题时，可从“关于”复制支持信息；请先阅读再分享。

## 从源码构建

构建要求与运行要求不同：当前源码需要**包含 macOS 27 SDK 的 Apple 工具链**，以及 `xcrun`、`swiftc`、`clang` / `clang++` 和 `codesign`。

下载或克隆源码后，在仓库根目录使用现有[构建脚本](scripts/build.sh)和[离线测试入口](scripts/test-offline.sh)：

```sh
./scripts/build.sh --adhoc
./scripts/test-offline.sh
```

App 输出至 `dist/0.1.44/Ez Audio Control.app`。构建与离线测试不会启动 App、安装驱动、写设备音量或请求音频捕获权限。`--adhoc` 仅用于本地开发；不包含发行者身份、Apple 公证或正式更新流程。也可使用 `--unsigned` 只编译。

构建完成后由你自行打开 App。保持安装路径和签名身份稳定有助于权限管理；开发签名变化后，macOS 可能需要你重新授权。不要通过修改 TCC 或关闭系统安全功能处理权限问题。

## 开发与反馈

[架构说明](Docs/ARCHITECTURE.md)介绍音量路由和恢复边界。[贡献说明](CONTRIBUTING.md)列出离线验证方法；[发布清单](Docs/RELEASING.md)区分源码、签名、公证与实机验收。

源码保留 DDC 显示器发现、`--diagnose` 只读诊断及历史控制代码。当前默认音量控制走 CoreAudio 原生音量或软件衰减，不将 DDC 硬件写入作为系统音量不可写时的后备方案。DDC 桥接使用私有 IOAVService/CoreDisplay 接口，兼容性可能随 macOS 改变；项目不承诺 Mac App Store 分发。

报告问题时说明版本、系统版本、连接方式、复现步骤与预期结果；不要上传完整系统日志、设备序列号或录音。安全问题请参阅 [SECURITY.md](SECURITY.md)。
