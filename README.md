# Ez Audio Control

轻量的 macOS 菜单栏音量工具。通过一个滑杆、音量键和紧凑 HUD，调节当前音频输出。

[English](README.en.md) · [MIT 许可](LICENSE) · [隐私说明](PRIVACY.md) · [参与开发](CONTRIBUTING.md)

## 能做什么

- 左键打开音量滑杆、输出设备列表；底部“声音设置…”直达 macOS 声音设置。
- 原生可调设备使用系统音量；系统不可写音量的输出自动尝试软件衰减，无需安装驱动。
- 统一处理键盘音量键与已映射为系统音量指令的鼠标操作，显示顶部 HUD。
- 列出已配对的蓝牙音频设备；用户点选后连接并切换输出。
- 支持 HUD、菜单栏数字、完整三种显示模式，中英文跟随系统语言。
- 可选音量反馈音效和登录时启动；软件模式反馈音跟随已确认的软件增益。

软件音量的 100% 是进入处理链路的原始音频，0% 是静音；只衰减，不放大，也不写显示器或外部音箱的硬件音量。

## 当前状态与要求

这是 **0.1.44 开发预览源码**。当前没有在此仓库提供已公证的正式下载包；请勿将本地构建当成正式发行版。

| 项目 | 要求或边界 |
| --- | --- |
| 架构 | Apple Silicon；未提供 Intel App 构建 |
| 系统 | 构建目标 macOS 14+；软件音量要求 macOS 14.2+ 与兼容的输出格式 |
| 开发工具 | 包含 macOS 27 SDK 的 Apple 工具链，需有 `swiftc`、`clang` 和 `codesign` |
| 依赖 | 仅系统框架，无第三方运行依赖 |
| 验证范围 | 当前开发机、离线假设备与组件检查；未宣称所有系统/设备兼容 |

睡眠、显示器唤醒和长时间运行的恢复仍在观察。软件音频链路清理或恢复时声音可能短暂中断；不能把软件衰减当作硬件音量上限或故障时的听力保护。第一次试用前，请暂停播放并把外部音箱调至安全音量。

DDC 桥接保留了私有 IOAVService/CoreDisplay 接口，兼容性可能随 macOS 改变。当前项目不承诺 Mac App Store 分发。

## 从源码构建

在项目根目录运行：

```sh
./scripts/build.sh --adhoc
./scripts/test-offline.sh
```

App 输出至 `dist/0.1.44/Ez Audio Control.app`。构建与离线测试不会启动 App、安装驱动、写设备音量或请求音频捕获权限。`--adhoc` 仅用于本地开发；不包含发行者身份、Apple 公证或正式更新流程。也可使用 `--unsigned` 只编译。

构建完成后由你自行打开 App。保持安装路径和签名身份稳定有助于权限管理；开发签名变化后，macOS 可能需要你重新授权。不要通过修改 TCC 或关闭系统安全功能处理权限问题。

## 使用与权限

1. 左键菜单栏图标，调节当前输出或点选设备。右键进入显示模式、音效和登录项设置。
2. 音量键需要你在系统设置中授予系统控制许可。新系统可能称“设备控制和数据访问”，旧系统称“辅助功能”；App 提供对应入口。
3. 不可原生调节的输出会尝试软件模式；首次 macOS 系统音频捕获提示由你决定。它处理系统输出音频，不读取物理麦克风，不保存音频。
4. 蓝牙许可只在你显式使用蓝牙入口时请求；App 不扫描新设备或自动配对。

只运行一份 App，避免多个音量工具同时处理同一条指令。遇到问题时，可从“关于”复制支持信息；请先阅读再分享。
